---

Implement the approved plan for a work item.

$ARGUMENTS can be: a work item ID, a path to `plan.md`, a spec folder path, or empty (uses `.claude/current-workitem`).

## Step 1 — Resolve plan.md

- Number → glob `specs/**/<number>-*/plan.md`, use first match.
- Ends with `plan.md` → use directly.
- Folder → append `/plan.md`.
- Empty → read ID from `.claude/current-workitem`, then glob.
- Not found → "No plan.md found. Run /write-plan first." and stop.

## Step 2 — Read context

1. Read `plan.md` fully.
2. Read `requirement.md` from same folder for acceptance criteria.

## Step 3 — Switch to correct branch

Derive branch from spec folder path: `specs/bugs/` → `fix/<id>-<slug>`, `specs/features/` → `feat/<id>-<slug>`.

- Already on correct branch → skip.
- Otherwise: try `git checkout <branch>` first. If fails, `git fetch origin develop` (fall back to `master`), then `git checkout -b <branch> origin/develop`.

## Step 4 — Full or delta mode

Check for `plan.snapshot.md` in the same folder:

**No snapshot → Full mode:** Read every file in "Affected Files" table, then implement all steps in order.

**Snapshot exists → Delta mode:** Compare `plan.snapshot.md` vs `plan.md`:
- New steps → implement
- Modified steps → re-implement
- Removed steps → ask user if cleanup needed (via `AskUserQuestion`, default: Yes)
- Unchanged → skip

Print delta before touching code:
```
Delta detected:
  + Step 3: <name> (new)
  ~ Step 1: <name> (modified)
  - Step 4: <name> (removed)
Skipping unchanged: 2, 5
```

## Step 6 — Execute steps

For each step (all in full mode; delta-only in delta mode):
1. Read relevant existing code first.
2. Make code changes per the plan (exact file paths, signatures, structures).
3. Confirm: `✓ Step N: <name>`

Handle removed steps (delta only, if confirmed): remove introduced code, but not code shared by active steps.

## Step 7 — Verify and finish

1. Verify each acceptance criterion is satisfied. Fix if not.
2. Save `plan.md` contents to `plan.snapshot.md` (only on full success).
3. Print summary:
   ```
   Implementation complete for <Type> #<ID>: <Title>
   Files changed:
   - created  path/to/new-file.ts
   - modified path/to/existing.ts
   All acceptance criteria satisfied.
   Snapshot saved to plan.snapshot.md
   ```

## Rules

- Do not deviate from the plan. If something unexpected arises, stop and tell the user.
- Do not modify files not in the "Affected Files" table (unless strictly necessary, e.g. index imports).
- Do not add extra features, refactor unrelated code, or fix unrelated issues.
- Follow existing code style, naming, and patterns, as codified in `docs/architecture.md` and `docs/convention.md`.
- **UI/UX rule:** When implementing any new UI/UX, build it as a serious enterprise application — professional, restrained, and discreet. Real users are hardcore domain experts and UI/UX specialists. Avoid a bare black-and-white look, avoid flashy colors, marketing gradients, playful illustrations, and emoji. Use a muted, considered palette, clear visual hierarchy, dense-but-legible typography, consistent spacing, and quiet interaction states (hover/focus/disabled). Reuse existing design tokens and components; do not introduce ad-hoc styles.

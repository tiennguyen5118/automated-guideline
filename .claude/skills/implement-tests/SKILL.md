---
name: implement-tests
description: Implement the tests described in a tests.md generated by write-tests, writing actual test files step by step. On subsequent runs after tests.md is updated, implements only the delta.
---

Write the tests described in the approved test plan.

$ARGUMENTS can be: a work item ID, a path to `tests.md`, a spec folder path, or empty (uses `.claude/current-workitem`).

## Step 1 — Resolve tests.md

- Number → glob `specs/**/<number>-*/tests.md`, use first match.
- Ends with `tests.md` → use directly.
- Folder → append `/tests.md`.
- Empty → read ID from `.claude/current-workitem`, then glob.
- Not found → "No tests.md found. Run /write-tests first." and stop.

## Step 2 — Read context

1. Read `tests.md` fully.
2. Read `requirement.md` from same folder for acceptance criteria.

## Step 3 — Resolve open questions

If "Open Questions" is non-empty: use `AskUserQuestion` (up to 4 per round). Make assumed values the default. Rewrite section with answers.

## Step 4 — Check test infrastructure

Read "Test Infrastructure" table. If framework is not installed (no config, no package.json entry) → print install command and stop.

## Step 5 — Full or delta mode

Check for `tests.snapshot.md`:

**No snapshot → Full mode:** Implement all test cases.

**Snapshot exists → Delta mode:** Compare `tests.snapshot.md` vs `tests.md`:
- New test files/cases → implement
- Modified cases → update
- Removed cases → ask user about deletion (default: Yes)
- Unchanged → skip

Print delta before writing.

## Step 6 — Implement tests

1. Read every source file referenced in the test plan (real signatures, types, paths).
2. Read any existing test files to avoid breaking working tests.
3. Implement in order: unit → integration.
   - Match framework, assertion style, and mocking library from "Test Infrastructure".
   - Follow existing test conventions (describe blocks, naming, imports).
   - Each test: matches described input/scenario, asserts expected output, is self-contained.
4. Confirm per section: `✓ Unit: N test cases written`

## Step 7 — Verify and finish

1. Check "Acceptance Criteria Coverage" — confirm each criterion has a test. Write minimal test if gap found.
2. Save `tests.md` to `tests.snapshot.md` (only on full success).
3. Print summary:
   ```
   Tests implemented for <Type> #<ID>: <Title>
   Files changed:
   - created  src/utils/math.test.ts  (3 unit tests)
   - modified src/api/todos.test.ts   (2 integration tests)
   Acceptance criteria: all N covered.
   Run: <runner command>
   Snapshot saved to tests.snapshot.md
   ```

## Rules

- Do not deviate from `tests.md`. If source code differs from plan, stop and tell the user.
- Do not modify source files — only test files.
- Do not add tests beyond `tests.md`. Mention gaps in summary instead.
